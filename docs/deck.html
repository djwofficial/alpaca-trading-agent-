The problem02 / 11

Autonomy and options don't mix by default

  • An unsupervised LLM placing multi-leg options trades can lose money fast — and the losses are hard to undo.
  • This competition scores P&L. A blow-up isn't a bug report, it's the final number.
  • A prompt is not a control. A model can be argued out of an instruction.

How do you get real autonomy and a hard floor under the downside?

Most "AI trading agent" demos are either not autonomous or not safe. We wanted both, and options make the safety problem sharp because the losses are fast and asymmetric.

The strategy03 / 11

Defined-risk put credit spreads on SPY

  • Sell a put, buy a lower-strike put, same ~8-day expiry.
  • Collect a net credit up front.
  • Keep it in full whenever SPY stays above the short strike — the common case.
  • Worst case = width − credit. Known before entry.

Liquid. Positive time decay. Resolves inside the competition window.

Every trade has a worst case we know at entry. That is the entire reason it is safe enough to hand to a model.

The edge04 / 11

Strike-picking is a coin flip. We don't compete there.

  • Every candidate reports the win rate it needs just to break even.
  • The market prices that within a hair of the true probability — so the "best-looking" spread is a coin flip with extra steps.
01

Selectivity

Trade only when the premium overpays for the risk. A skip costs nothing, and most days are a skip.
02

Exits

Cut a loser before it reaches max loss. Losses here run 7–10× the size of a win.

One avoided max-loss is worth many collected credits.

This is the honest core of the pitch. No magic signal — just a disciplined operator that skips most days and cuts losers early, which is a job an LLM inside a hard cage can actually do.

Architecture05 / 11

Code is the supervisor. The model is the judgment.

Market dataalpaca-py: account, chain, quotes, clock
→
Candidate finderenumerate every legal spread, price it conservatively
→
Risk gatesveto anything unsafe — functions that return False
→
LLM brainpick one pre-approved candidate, or skip
→
Executorre-checks the gate, dry-run by default
→
Journalevery decision + reasoning, JSONL

The brain only ever chooses from a menu the gates already approved. It cannot invent a strike, size past the cap, or go naked — whatever it returns is clamped to something legal before it reaches Alpaca.

The model never places a trade. It picks an index off a list the code built and the gates already cleared.

The brain07 / 11

The worst a confused model can do is take a legal trade or stand aside

  • Judgment model: Claude Opus-class, structured output. Entry decisions think harder than exit checks — they're rarer and irreversible.
  • On entry it commits a thesis and an invalidation — concrete and checkable: "SPY closes below 758, or −1.5% intraday."
  • Every later cycle the exit check asks one question: has that happened? An unrealised loss alone is not a reason to close.
  • _sanitize_entry clamps whatever the model returns. Out-of-range → skip.
  • A deterministic fallback runs with no API key. A model outage degrades to inaction — never to a blind trade.

The invalidation is a pre-commitment: the model writes down what would change its mind before it has a position, so it can't rationalise its way into holding a loser later.
